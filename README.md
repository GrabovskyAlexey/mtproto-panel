# MTProto Panel

Веб-панель управления MTProto прокси серверами. Позволяет централизованно управлять несколькими сервис-нодами, создавать и настраивать прокси, просматривать статистику и следить за подключениями.

## Возможности

- Управление несколькими сервис-нодами с единой панели
- Создание / редактирование / удаление MTProto прокси
- **VPN-туннелирование** — указание VLESS-подписки для прокси (трафик через зарубежный сервер)
- **Мультипортовые прокси** — назначение индивидуального порта каждому прокси
- Просмотр статистики: CPU, RAM, трафик, аптайм
- Подключённые IP-адреса с флагами стран
- Лимиты подключений на прокси (ограничение устройств)
- Чёрный список IP-адресов на уровне ноды
- Пользовательские домены для fake TLS (пул 50 доменов по умолчанию)
- Копирование ссылки `tg://proxy?...` в один клик
- Приостановка / возобновление прокси
- Обновление сервис-ноды из панели
- JWT авторизация
- Полностью на русском языке

## Совместимость

Скрипт автоматически установит недостающие зависимости: `curl`, `openssl`, `git`, Docker, Docker Compose.

## Быстрая установка

Одна команда для загрузки и запуска:

```bash
bash <(wget -qO- https://raw.githubusercontent.com/GrabovskyAlexey/mtproto-panel/master/install.sh)
```

Скрипт автоматически:
1. Установит Docker и Docker Compose (если отсутствуют)
2. Скачает последнюю версию из ветки `master`
3. Запросит настройки:
   - **Порт панели** (по умолчанию `80`)
   - **Логин администратора**
   - **Пароль администратора**
4. Сгенерирует JWT-секрет и пароль БД
5. Соберёт и запустит все контейнеры

Панель установится в `/opt/mtproto-panel`.

## Обновление

```bash
cd /opt/mtproto-panel
sudo bash update.sh
```

Скрипт переключает `origin` на `GrabovskyAlexey/mtproto-panel`, получает код и загружает образы `ghcr.io/grabovskyalexey/mtproto-panel-backend:latest` и `ghcr.io/grabovskyalexey/mtproto-panel-frontend:latest`. При недоступности реестра выполняется локальная сборка. Контейнеры заменяются после загрузки образов; база данных, `.env`, пароли и сертификаты сохраняются. Старая SSL-конфигурация установщика переводится на новую схему портов автоматически.

Для первого перехода со старого репозитория после публикации кода и успешной сборки обоих образов запустите новый скрипт:

```bash
cd /opt/mtproto-panel
curl -fsSL https://raw.githubusercontent.com/GrabovskyAlexey/mtproto-panel/master/update.sh | sudo bash
```

После этого доступно обычное обновление через `update.sh` или кнопку в настройках панели. Обновление из интерфейса продолжается в отдельном контейнере, который не завершается при перезапуске backend.

GitHub Actions уже публикует образы в namespace владельца репозитория после push в `master` или `dev`, а также ручного запуска workflow. Для установки без авторизации переведите новые пакеты GHCR в Public. Перед обновлением дождитесь завершения сборки backend и frontend.

| `DB_PASSWORD` | Пароль БД |

## Использование

Панель занимает только выбранный внешний порт: например, при `PORT=89` без SSL используется `89:80`, а с SSL — `89:443`. С SSL установщик создаёт отдельную конфигурацию nginx и подключает сертификаты.

1. Откройте панель: `http://SERVER_IP:PORT`
2. Войдите с логином и паролем администратора
3. Добавьте сервис-ноду (IP, порт, токен)
4. Создавайте прокси, управляйте лимитами и чёрными списками

### Статус VLESS

У прокси с VLESS в карточке и статистике показывается отдельный результат проверки: соединение проверено, проверка не прошла, контейнер остановлен или статус неизвестен. Нода выполняет HTTPS-запрос к `www.gstatic.com/generate_204` через SOCKS5 своего Xray; успешный результат подтверждает передачу трафика через туннель в момент проверки. Он не проверяет отдельно доступность Telegram. Ошибка может означать также недоступность контрольного ресурса.

Результат кешируется на 30 секунд. Карточки обновляются каждые 30 секунд, статистика — каждые 10 секунд. Успешный результат старше 90 секунд отображается как неизвестный. Старые ноды без поля `vpnStatus` продолжают работать; для получения результата нужно обновить ноду.

Для этой функции обновите и панель, и ноду до образов из ваших репозиториев. Порядок обновления описан выше; у ноды используйте её `update.sh`.

Проверки протокола основаны на [SOCKS5 (RFC 1928)](https://www.rfc-editor.org/rfc/rfc1928) и [TLS API Node.js](https://nodejs.org/api/tls.html); сертификат контрольного ресурса проверяется.

## Развёртывание в России с VPN

Для работы MTProto прокси в РФ трафик до Telegram нужно пропускать через зарубежный VPN-сервер.

### Схема

```
Пользователь (РФ)
       │
       ▼
┌─────────────┐     ┌───────────────────┐     ┌──────────────┐     ┌─────────────┐
│  Панель     │────→│ Сервис-нода (РФ)  │────→│ VPN-сервер   │────→│ Telegram DC │
│  (любой IP) │     │ telemt + xray     │     │ (за рубежом) │     │             │
└─────────────┘     └───────────────────┘     └──────────────┘     └─────────────┘
```

### Инструкция

1. Установите панель на любом сервере (может быть в РФ)
2. Установите сервис-ноду на российский сервер
3. Подготовьте VPN-сервер за рубежом с xray/VLESS (Reality рекомендуется)
4. В панели при создании прокси укажите URL подписки VLESS
5. Сервис-нода автоматически создаст xray-туннель и проксирует трафик

### Поддерживаемые VPN-протоколы

| Протокол | Транспорт | Рекомендация |
|----------|-----------|--------------|
| VLESS + Reality | TCP | Лучший выбор — не детектируется DPI |
| VLESS + TLS | TCP / WS / gRPC | Хорошо работает |
| VLESS | TCP | Базовый вариант |
